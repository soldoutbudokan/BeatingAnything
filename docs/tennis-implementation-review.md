# N2/N3 implementation decisions before results

Recorded September 8, 2026 before either tennis validation or holdout evaluation. These clarify chronology and source handling in the already frozen protocols. No profitable output has been used to select them.

- The source collector fixes each Tuesday/Friday list of at most twelve Challenger IDs from fixture metadata before normalizing scores or reading detail odds. Raw responses and per-date sample pins are hashed and immutable; failed requests and parse failures remain in an append-only attempt ledger. No failed sample is replaced. Evaluation requires an attempt for all 1,826 calendar dates and all selected detail pages; an unfinished download is not a completed experiment. A failed daily page leaves its sample unknown, not an invented empty sample.
- Stable identities use TennisExplorer match IDs and exact player URL slugs. Player ordering can be canonicalized by swapping both identities and set-score sides, preserving every set winner. Repeated event IDs across source dates use their latest source result date for availability; conflicting same-date scores or identities fail. The full repeated-date audit remains visible. This conservative treatment cannot certify when a retrospective source first published a score.
- A source date ends at the next Europe/Prague midnight. Its results become available 48 elapsed hours after that instant. Rolling windows use source date-end instants in `(decision - window, decision]` and also require availability by the decision. Lifetime set Elo has no decay. An event's own history is excluded; an impossible earlier availability triggers a complete causal Elo replay without that event, including its indirect effects on other players.
- Recognized conventional completed sets contribute to Elo and tiebreak-rate history even in a retirement. Workload requires a fully recognized completed best-of-three two-set win. Unknown player history is flagged; it is not presented as a known debut or proof of complete source coverage.
- Current-match outcomes and close validity never determine whether an entry's features are accepted. An unresolved or mismatched result stays ungraded in the accepted forecast population. No missing close removes a selected bet. Current price cells, current rankings and later head-to-head summaries are not predictors.
- Annual fitting uses only previous-year labels available before the earliest eligible quote in that fold. Hyperparameter selection also has an availability time: the last delayed 2023 validation label. A 2024 event whose quote predates that moment cannot receive a model selected with those labels; its ID is explicitly reported as model-unavailable, with no hypothetical bet. This is a chronological deployment restriction applied before inspecting returns, not selection on performance. The remaining fold gets one fixed annual fit.
- Empty declared splits produce an explicit insufficient-data report. Numerical, parsing and integrity exceptions fail the run instead of masquerading as an unfavorable experiment. Both N2 and N3 and all three candidates per experiment remain separately reported; no holdout-based selection between them is allowed.
- The newly frozen F1 FanDuel pilot adds two further evaluations to the eleven previously reserved comparisons. Before any tennis outcome evaluation, the primary family allowance is therefore increased to thirteen: confidence `1 - 0.05/13 = 99.6153846%`, 10,000 calendar-week bootstrap samples, seed 1729. Prior recorded protocols and negative results remain preserved. More searching would require another explicit adjustment and genuinely new evaluation evidence.

These changes do not establish an edge, executable FanDuel prices, verified closing ticks, or prospective qualification. The paused/active state of the assistant's task is also not evidence that an external market collector is running; that requires a live process or workflow handle.
